BAGIAN 1: ALUR UTAMA (SYNC & SCRAPE)
Setiap update metrik mencakup GROUP (Y/X) dan ADMIN (Y/X).
Daftar grup di device dibaca di Electron/sidecar (bukan isi pesan). Pencocokan master↔daily di Postgres RPC.

A. SYNC — cek kolom session:
VALID: tanpa modal login → hitung grup+admin di device → update grid → [Now|Later] atau resume-empty (0 grup).
INVALID: modal login → sukses: save session, update group+admin, tutup login → [Now|Later].
Login FAIL: WA auto-QR; TG error + pesan (tanpa auto-loop). Tutup modal = batalkan, session tetap INVALID.

B. SCRAPE (hanya lewat Sync → Scrape Now; kolom Last update read-only):
VALID (+ probe device; gagal → login meski grid valid): langsung scraper.
INVALID: login → sukses → auto-scrape tanpa Now/Later.

BAGIAN 2: KOLOM LAST UPDATE (real-time)
STANDBY: INVALID → "Use Sync (↻) to log in first"; VALID+MATCH → timestamp saja; VALID+NOT MATCH → timestamp; pending → "—".
RUNNING: bar + X/Y + marquee "Reading groups…".
SELESAI: update group+admin + timestamp; MATCH/NOT MATCH seperti standby.
Tidak ada tombol Run di grid — scrape hanya dari modal Sync.

BAGIAN 3: MODAL LOGIN & QR
Panel lebar (min ~36rem), kotak QR besar (~14rem), skeleton saat generate, overlay expired/gagal + tombol Refresh QR.
WA: auto-regenerate QR. TG: error dulu, refresh manual.

BAGIAN 4: PERFORMA (3000 grup)
- quickDeviceCount: hanya total dari device; tidak merge ribuan group_id ke daily di renderer.

BAGIAN 5: CLEAR SESSION (tombol X di kolom Session Valid, hover baris)

Sync berikutnya → open_login (QR bersih). Bukan remove slot. File: clearAccountSession.ts, useAccountSyncFlow.handleClearSession.

BAGIAN 6: METRIK GRID, ISSUE & MODAL GROUP LINK (satu engine)
- Y/X groups & admin: accountMasterDailyCompare.ts — dedupe group_id raw; X = master brand.
- Kartu Issue: buildTicketSummariesFromEngine.ts — angka dari engine (bukan hitung baris DB mentah).
- Breakdown ticket: computeAccountTicketBreakdown (in-memory; sama dengan grid).
- Modal Admin vs master list: fetchAccountGroupLinks — hanya baris master (X).

- Grid: kolom On device (groupsCurrent), In brand (joinedInMaster/groupsTotal), Last update (timestamp read-only).
- Export group link: RM-[nama akun]-YYYYMMDD.xlsx.

BAGIAN 7: SESSION PROBE & RESOLVE AKUN (1.0.17)
- Probe device VALID+Sync/Scrape: timeout 20s, retry busy — bukan skala grup; busy → alert SESSION_CHECK_BUSY (bukan modal login).
- Device key = messaging_accounts.id baris grid (accountSessionResolve.ts); bukan label global.
- shouldInvalidate DB hanya session mati (UNPAIRED/logout), bukan timeout/busy.

BAGIAN 8: DATA FRESH & REALTIME (1.0.17+)
- Scrape: RPC rm_commit_account_scrape atomik (DELETE daily → INSERT → rebuild master).
- Patch grid: patchAccountGridAfterDailyWrite; realtime group_scrape_daily → onAccountDailyChanged (tanpa double-patch master).
- Reload Reporting + Operations: scheduleMonitoringReload di GroupMonitoringProvider (debounce 500ms) — bukan dispatch ganda dari caller scrape.
- Reporting: fetch langsung DB + dedupe scraped_at; reload via rm-reporting-reload.
- Matrix filter kolom Yes/No kosong: header tabel tetap + Back to all groups.
