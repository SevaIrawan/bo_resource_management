Architecture Plan: Telegram Integration to GM

Document information
ScopeTelegram accounts, all brands (MYR & SGD)
ToolsGM Apps (Group Monitoring)

1. Background

GM Apps was built to monitor and manage WhatsApp accounts per brand. Telegram will be integrated as a second platform into GM, following the same architecture as WhatsApp.

2. Technical Framework: WhatsApp and Telegram in GM

Telegram will be built following the exact same pattern as WhatsApp in GM. One Job Queue, one Worker Settings, one way of calculating Aligned, Junk, and Review for both platforms. The only difference is the connection layer to the platform itself.

LayerWhatsApp (already running)Telegram (to be built)
Connection to platformPuppeteer/Chrome, runs directly inside the Electron appSeparate Python sidecar (Telethon), the Electron app talks to this sidecar over HTTP
Jobs neededCreate group, Join by invite link, Set admin, Set group photo, Leave group, Delete group, Exit and delete groupThe same seven job types, built following the WhatsApp pattern
Aligned/Junk/Review calculationOne system, no logic split by platformUses the same system, no new logic needed

What needs to be provided specifically for Telegram, since it does not exist for WhatsApp:

  • 11 admin right settings per role (WhatsApp only has 3)
  • Automatic handling when hitting Telegram's rate limit (FloodWait, auto-sleep up to 7200 seconds)
  • Automatic retry when fetching an invite link fails

3. Data Layer

WhatsApp and Telegram write to the same Supabase tables (group_scrape_daily, groups_master), through one RPC (rm_commit_account_scrape) that takes a platform parameter. There is no separate table or RPC per platform, only a platform column that distinguishes the rows.

4. Packaging and Deployment

The Telegram Python sidecar (rm-telegram-sidecar.exe) will be packaged into the installer alongside the main Electron app, the same way the Puppeteer/Chrome dependency is packaged for WhatsApp. Users do not need a separate installation, one installer file covers both.

5. Resource Isolation Between Platforms

WhatsApp and Telegram have separate quotas across two execution lanes:

LaneWhatsApp quotaTelegram quota
Main execution (Job Queue, Sync, manual Scrape)10 accounts active at once10 accounts active at once
Scheduled auto scrape6 sessions active at once6 sessions active at once

Both lanes are counted and capped separately per platform, so a surge in usage on one platform does not eat into the other platform's quota.

6. Auto Scrape

The Automatic account scrape feature (scheduled sync in Settings) applies to both platforms through one shared module (autoScrapeLane.ts), not a separate module for Telegram.

The difference: WhatsApp auto scrape needs a dedicated Chrome pool (waAutoScrapeBrowserPool.ts) so it does not compete for browser instances with the Chrome the user is actively using. Telegram does not need an equivalent pool, since its auto scrape runs through the same sidecar as manual scrape, with no separate browser process involved.

7. Login Session Storage

WhatsApp stores its login session in a local folder on the PC (wa-sessions); the database only stores its status flag. A WhatsApp session is tied to one PC, and cannot be moved to another PC without logging in again.

Telegram stores its login session as a string in the database, not in a local file. A Telegram session is portable, it can be used from another PC as long as the data in the database is still valid, with no need to log in again on every PC change.

8. Scope

Applies to all Telegram accounts across all brands (MYR & SGD).
