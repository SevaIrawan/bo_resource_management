1. Overview

Desktop application to monitor and operate many WhatsApp and Telegram accounts per marketing brand. All business data (accounts, groups, master list, tickets, sessions) is stored in Supabase. Platform login (WA/TG) runs in the Electron main process with local sessions per PC.

Users: internal company teams (not a public product).

v1.0.23 highlights:

  • WA scrape fetches invite links from device → writes daily → rebuilds master
  • Puppeteer stability (protocolTimeout, metadata concurrency, retry)
  • Job Queue: VIEW detail per task + Excel export
  • Real-data validator (validate:real-operations-data)

5.2 Sync & Run Scraper

  • Sync (↻): probe device session → update group/admin counts → prompt Scraper Now / Later
  • Run Scraper: full device scrape → write daily → rebuild master → reconcile tickets → realtime UI refresh
  • Later: close modal without scraping
  • Cancel scrape: full stop + release Chrome

Scale: up to ~3000 groups per account (WA store cap + measured timeouts).

5.3 Platform Login

Clear Session (X): purge WA disk + invalidate DB → clean re-login.

5.5 Account Management

10. Scrape Data Pipeline (Production Contract)

Device (WA Electron / TG sidecar)
  → runAccountScraper
  → DELETE daily (account_id)
  → INSERT group_scrape_daily
      (group_id, group_name, invite_link, counts, is_admin)
  → RPC rm_rebuild_brand_groups_master
      (only valid invite_link enters master)
  → reconcileTickets + refresh grid/ticket/reporting

WA scrape v1.0.23:

  • Phase 1: parallel group metadata (concurrency 4)
  • Phase 2: serial invite link per admin group (getInviteCode)
  • Puppeteer protocolTimeout 10 min + ProtocolError retry

TG scrape: invite via username or ExportChatInviteRequest (sidecar).
