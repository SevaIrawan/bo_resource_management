## 1. 概述

### 1.1 本应用做什么？

资源管理帮助团队完成以下工作：

| 能力 | 说明 |
|------|------|
| 多账号登记 | 按**品牌**（如 SBMY）登记多个 **WhatsApp** 与 **Telegram** 账号 |
| 会话健康 | 检查账号在手机/本机是否仍**在线**（会话） |
| 群组对齐 | 对比**设备上的群**与**品牌标准群清单**（主表） |
| 抓取 | 从设备完整读取群组并写入数据库 |
| 工单 / 问题 | 查看需修复项（缺标准群、非管理员、重复、设备多余群等） |
| 导出 | 将筛选结果导出为 **Excel**，供现场作业使用 |

### 1.2 两种「登录」

请勿混淆 — 用途完全不同。

| 类型 | 用途 | 操作方式 |
|------|------|----------|
| **仪表板登录** | 进入应用 | **用户名** + **密码**（由 IT 提供，对应 `users` 表） |
| **平台登录** | 将 WA/TG 关联到营销账号 | 点击 **同步 (↻)** → 二维码或手机号登录弹窗 |

仪表板密码**不是** Telegram 或 WhatsApp 的密码。

### 1.3 什么**不会**生成工单？

**会话**列中的登录/登出变化**不会**产生工单。工单仅针对相对品牌标准的**群组与管理员**问题。

## 2. 启动应用

### 2.1 安装（每台 PC 一次）

1. 运行 IT 提供的 **`Resource Management Setup x.x.x.exe`**。
2. 按安装向导完成 **安装**。
3. 从**桌面快捷方式**打开应用。
4. **无需**手动填写 `.env` — 组织配置已包含在安装包中。

详细 Windows 步骤见 [INSTALL-WINDOWS.md](../../INSTALL-WINDOWS.md)。

### 2.2 仪表板登录

| 步骤 | 操作 |
|------|------|
| 1 | 输入 **用户名** 与 **密码** |
| 2 | 点击 **登录** |
| 3 | 若失败 | 联系 IT — 可能尚未在数据库中创建账号 |

**登录页界面文案：** 用户名、密码、**登录**，副标题 *Telegram 与 WhatsApp 运营*。

**常见提示：**

| 提示 | 含义 | 处理 |
|------|------|------|
| 用户名或密码错误 | 凭据不正确 | 向 IT 核实 |
| 数据库未配置，请检查 .env 文件 | 本机 Supabase 未配置 | IT：重装或打开配置文件夹 |
| 应用配置不完整。请联系 IT… | 安装包未包含组织配置 | IT：使用含组织配置的最新安装包重装 |

### 2.3 登录之后

进入 **群组监控** 主界面，默认显示 **账号** 标签。

| **卡片视图 / 表格视图** | 右侧 | 按品牌卡片 或 合并单表 |
| **导出**（下载图标） | 右侧 | 导出**当前筛选条件下**的账号 Excel |

占位符：*搜索账号名 / 电话号码…*

### 4.2 品牌卡片（卡片视图）

每个品牌（如 **品牌：SBMY**）对应一张卡片。

#### 品牌标题区

| 元素 | 功能 |
|------|------|
| **箭头** | 折叠 / 展开账号表 |
| **品牌标题** | 品牌名称 |
| **账号数量** | 如 *12 个账号* |
| **WhatsApp 标准 x / Telegram 标准 x** | 各平台标准（主表）群数量 |
| **全部已对齐** / **x 个账号未对齐** | 该品牌数据健康摘要 |
| **+ 添加** | 添加新账号（选择 WA 或 TG） |
| **X（从列表移除此卡片）** | 确认后从数据库删除品牌及相关数据 |

#### 添加账号（+ 添加）

| 步骤 | 操作 |
|------|------|
| 1 | 点击 **+ 添加** |
| 2 | 选择 **WhatsApp** 或 **Telegram** |
| 3 | 填写 **账号名称**（团队标签，如营销姓名） |
| 4 | 填写 **账号电话号码**（建议填写；TG 可用 @username） |
| 5 | 点击 **保存** |

**空账号槽位：** 显示 *空账号槽位* 的行 → 点击 **添加账号** 填充槽位，不会在槽位外额外增行。

### 4.3 账号表列说明

| 列名 | 含义 | 如何理解 |
|------|------|----------|
| **账号** | 平台 + 名称 + 电话 | WA/TG 图标、名称、下方号码 |
| **品牌** | 品牌名 | 本卡片内各行相同 |
| **状态** | **在线** = 会话有效；**已登出** = 无效 | 绿 / 红指示 |
| **会话** | **有效** / **无效** | 无效时需先登录；**有效时悬停 X** = **清除会话** |
| **群组** | `Y/X` | Y = 当日设备群数；X = 该平台品牌标准群数 |
| **设备上** | 单个数字 | 手机/本机群总数（daily） |
| **品牌内** | `y/x` | 已加入品牌主表的群数 / 主表总数 |
| **管理员** | 进度条 + `a/X` | 您为管理员的群数 vs 标准 |
| **抓取** | **运行** + 时间 / 进度 | 完整读取群组并写入数据库 |
| **操作** | **群链接** | 打开群列表与邀请链接 |

**重要：** WhatsApp 与 Telegram 的数量**分开统计**，不可在同一行跨平台比较 `Y/X`。

### 4.4 行内控件

| 控件 | 功能 |
|------|------|
| **↻（同步）** | 主流程：平台登录或检查本机会话并更新计数 |
| **X（悬停于名称右侧）** | **移出槽位** — 删除账号并重建品牌主表（确认弹窗） |
| **X（悬停于会话列，仅有效）** | **清除会话** — 本机与数据库登出；下次同步打开全新二维码 |
| **群链接** | 弹窗：daily 七列或管理员对比主表 — 需先有抓取数据 |

提示文字：**同步账号**。

### 4.5 **同步 (↻)** 流程 — 必读

行为取决于 **会话** 列取值。

#### 会话 = **无效**

| 步骤 | 说明 |
|------|------|
| 1 | 点击 **↻** |
| 2 | 打开平台登录弹窗（默认二维码，或手机号登录） |
| 3 | 在营销手机上扫码（WA：已关联的设备；TG：设置 → 设备 → 链接桌面设备） |
| 4 | 成功后：会话保存，群组数字更新 |
| 5 | 可能提示 **抓取** — 将完整群列表写入数据库 |

#### 会话 = **有效**

| 步骤 | 说明 |
|------|------|
| 1 | 点击 **↻** |
| 2 | 应用检查本 PC 上 WA/TG 是否仍活跃 |
| 3 | 正常：更新 **群组** / **管理员** 数字 |
| 4 | 失败：提示重新登录 |

**说明：**

- 平台登录仅在**桌面客户端**内完成（不能仅靠浏览器）。
- 若约 10 秒内未显示二维码：关闭窗口，等待数秒后再次 **同步**。
- Telegram 群很多时同步超过 3 分钟：重试或重启应用。

### 4.6 **抓取** 列 — **运行** 按钮

| 条件 | 显示 | 操作 |
|------|------|------|
| 会话无效 | *请先点击同步 (↻) 登录* | 先同步 |
| 已对齐 | 仅显示 **最后更新** 时间 | 通常无需运行 |
| **未对齐** | **运行** + 时间戳 | 点击 **运行** → 从手机读取全部群 → 写入 DB → 工单刷新 |
| 运行中 | *读取群组中…* / 进度 | 等待（群多时可需数分钟） |

| 术语 | 含义 |
|------|------|
| **运行 / 运行抓取** | 完整抓取 — 全部群写入数据库 |
| **同步** | 检查会话 + 汇总计数 — 不一定是完整抓取 |

登录成功后可能提示：*登录成功，设备群组与管理员数已更新。是否立即抓取并写入数据库？* → 选 **抓取** 或 **稍后**。

### 4.7 **群链接** 弹窗

通过 **操作 → 群链接** 打开。选择模式：

| 模式 | 列表内容 |
|------|----------|
| **本账号全部群组** | 设备上全部群（Y）— daily 抓取快照 |
| **管理员 vs 主数据** | 仅 **品牌主数据** 群（X）+ 本账号加入/管理员状态 |

| 功能 | 说明 |
|------|------|
| 表格（daily 模式） | 序号、群名称、群 ID、成员数、管理员数、是否管理员、邀请链接 |
| Excel 导出 | `RM-[账号名称]-YYYYMMDD.xlsx` |
| 管理员筛选 | 全部 / 仅管理员 / 非管理员 |
| 分页 | 群多时 **上一页** / **下一页** |

**管理员 vs 主数据** 的总数与群组/管理员列分母（X）及卡片 **WA x Group** 徽章一致 — 不包含设备 junk 群（见工单 → Junk）。

列表为空？先 **运行抓取**。提示：*无链接，请先抓取。*

### 4.8 从槽位移除账号

| 步骤 | 操作 |
|------|------|
| 1 | 悬停账号行 → **X** 图标 |
| 2 | 确认 *移出此槽位？* → **移除** |
| 3 | 效果 | 数据库中账号停用；本机设备会话清除（WA：删除本机认证） |

在将测试账号换为正式营销账号前使用 — 或由 IT 在数据库中删除（见 §7）。

### 4.9 添加品牌卡片

卡片列表末尾：**添加卡片** → 输入品牌名称 → **创建卡片**。

### 4.10 表格视图

所有品牌合并为**一张表**，列与卡片视图相同。工具栏筛选与导出仍然生效。

### 4.11 平台登录弹窗（参考）

| 模式 | WhatsApp | Telegram |
|------|----------|----------|
| 二维码 | 已关联的设备 → 关联新设备 | 设置 → 设备 → 链接桌面设备 |
| 手机号 | 在手机上输入配对码 | 短信验证码 / 两步验证密码 |

弹窗操作：关闭、二维码 ↔ 手机号切换、验证、连接成功后 **确定**。

| 问题 | 界面提示 | 处理 |
|------|----------|------|
| 10 秒无二维码 | *10 秒内未显示二维码。请关闭窗口…* | 关闭等待后再次同步 |
| Telegram 二维码超时 | *Telegram 二维码超时…* | 重启应用；IT 检查 `.env` 中 API 配置 |
| WhatsApp 二维码超时 | *WhatsApp 二维码超时…* | 重启；确保本机可连接 WhatsApp Web |

## 5. 「工单」标签 — 问题与修复

### 5.1 何时出现工单？

账号完成抓取/同步后，系统比对**设备群（每日快照）**与**品牌主表**。存在差异则自动生成工单。

工单卡片数字与账号页的群组/管理员列使用 **同一套引擎** — 不是数据库原始行数。

### 5.2 工单类型（筛选：**全部工单类型**）

| 类型（界面） | 简要含义 | 常见现场操作 |
|--------------|----------|--------------|
| **缺标准群** | 品牌主表有、本账号无 | 入群（用导出邀请链接） |
| **非管理员** | 已在群但非 Admin | 申请管理员 |
| **群数不一致** | 设备群数 ≠ 品牌标准 | 核对并对齐 |
| **群 ID 重复** | 相同 ID、名称冲突 | 核对主表数据 |
| **群名重复** | 同名不同 ID（主表） | 核对主表数据 |
| **设备多余群** | 手机有、主表无 | 在手机上清理/退群 |

会话登录/登出**不会**生成工单。

### 5.3 工单工具栏

| 工具 | 功能 |
|------|------|
| 搜索 | *搜索账号 / 群组…* |
| 品牌 / 平台 / 类型筛选 | 缩小工单列表 |
| **书签：进行中** | 任务状态为「进行中」的工单 |
| **书签：已完成** | 任务状态为「完成」的工单 |
| **导出** | 导出**当前筛选条件下**的全部工单 Excel |

**工单进度视图：** 进行中 · 已完成

### 5.4 工单卡片

每张卡片 = 一个账号 + 品牌 + 工单类型的**一个问题**。

| 区域 | 内容 |
|------|------|
| 标题 | 账号名称 |
| 徽章 | 工单类型（颜色区分） |
| 平台 | WA / TG |
| 元信息 | 电话 · 品牌 |
| 描述 | 摘要（群数量、标题说明） |
| **处理** / **新** / 状态说明 | 工作流 — **单击** 打开处理表单 |
| **双击卡片** | 完整**明细**表（全部群组行） |

卡片提示：*双击查看完整明细表*

### 5.5 **处理工单** 弹窗（工作流）

| 字段 | 功能 |
|------|------|
| **任务状态** | 待办 → 进行中 → 完成 / 中断 |
| 任务截止日期 / 备注 | 写入数据库（`ticket_issue_handles`） |
| **保存** | 保存并关闭 |
| **导出** | 仅导出本工单 Excel |

书签 **进行中** / **已完成** 与保存的任务状态一致。

### 5.6 明细弹窗（双击）

| 功能 | 说明 |
|------|------|
| 完整表格 | 本工单涉及的全部群 |
| **导出** | 现场修复参考 |
| 关闭 | **Esc** 或点击外部 — **关闭** |

### 5.7 工单 ↔ 账号 关系

| 步骤 | 操作 |
|------|------|
| 1 | 在手机上修复群（入群、管理员、清理多余群） |
| 2 | 在对应账号上 **同步** 或 **运行抓取** |
| 3 | 数据对齐后工单减少或关闭（数据库更新后实时反映） |

手机上已修复但工单仍在：**运行抓取** 以推送最新设备数据。

#### 账号自动同步

| 选项 | 功能 |
|------|------|
| **启用** | 应用打开时在后台执行（与每账号 **同步** 相同逻辑） |
| **间隔（分钟）** | 执行频率（默认常为 60 分钟） |

带时间戳写入数据库。在尚无抓取数据时，**不能**替代完整的 **运行抓取**。

管理页摘要显示：*开 · N 分钟* 或 *关*。

#### 语言

| 选择 | 效果 |
|------|------|
| **English** | 界面为英文 |
| **中文** | 界面为简体中文（与本文术语一致） |

更改后立即作用于仪表板文案。

## 7. 数据同步（实时）

### 7.1 数据库变更 → 已打开的应用

当 IT 或系统在 **Supabase** 中修改数据（账号、工单、主表群、会话标记）时：

| 行为 | 说明 |
|------|------|
| 实时刷新 | 已打开的应用在数秒至数分钟内更新 |
| 无需重装 | 仅数据变更不需要新安装包 |

示例：IT 删除测试账号 → 所有用户仪表板上该行消失。

### 7.2 代码 / 界面变更 → 应用更新

需通过**新版本**（自动更新 + **重启**）。见 [PROJECT.md §4.4](../../PROJECT.md)。

| 变更类型 | 交付方式 |
|----------|----------|
| Supabase 数据 | 实时 |
| 新按钮、布局、逻辑 | 新版 `.exe` |

### 7.3 本机与云端存储

| 位置 | 内容 |
|------|------|
| **云端（Supabase）** | 品牌、账号、群、工单、会话标记 |
| **本机（AppData）** | 每账号 WhatsApp 认证、自动同步偏好、语言 |

## 10. 常见问题

**应用更新需要重新安装吗？**  
不需要。收到更新提示后**重启**即可（IT 已发布到 GitHub 时）。

**在 Supabase 删除数据会删掉安装程序吗？**  
不会。仅影响仪表板数据。

**会话显示有效，但运行抓取仍要求登录？**  
本机可能已失去设备会话 — 点击 **同步** 重新检查。

**群组显示 `12/21` 是什么意思？**  
设备检测到 12 个群；21 为该平台的品牌标准群数（WA 与 TG 分开计）。

**一台 PC 可以挂很多 WhatsApp 账号吗？**  
可以，支持大量账号，但每个账号需单独扫码；Chrome 并发进程约限制为 4 个左右。

**手机上已修复，工单还在？**  
点击 **运行抓取** 或 **同步**，让最新设备数据进入数据库。

**仪表板登录失败？**  
联系 IT — 需在 `users` 表中开通账号。

**Telegram 二维码或登录报错？**  
联系 IT — 检查 Telegram API 配置与数据库迁移 `023`。

**卡片视图和表格视图有何区别？**  
数据相同；卡片按品牌分组，表格为扁平列表。

**从列表移除此卡片会删除品牌吗？**  
会 — 确认后从数据库删除品牌及相关数据。

**二维码报错「still starting from previous attempt」？**  
本机 WhatsApp 会话卡住 — 等待数秒，或对**有效**会话列使用 **清除会话 (X)** 后重新同步。

**其他同事能否同步我登录的账号？**  
WhatsApp 不行 — 授权在本机。需 **清除会话** 后由对方在本机扫码。

**在哪里改界面语言？**  
**管理** → **偏好设置** → **语言** → English 或 **中文**。
