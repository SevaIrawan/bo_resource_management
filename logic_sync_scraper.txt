BAGIAN 1: ALUR UTAMA (SYNC & SCRAPE) — acuan = SESSION UI
Setiap update metrik mencakup GROUP (Y/X) dan ADMIN (Y/X).
Daftar grup di device dibaca di Electron/sidecar (bukan isi pesan). Pencocokan master↔daily di Postgres RPC.
Scrape = data device nyata (bukan palsu/mock). Akun hingga ~5000+ grup per akun.

A. SESSION UI = VALID → Sync:
   1. Check Session **real ke device** (bukan disk/fake).
   2. Device VALID → modal **Scrape Now | Later**
      - **Scrape Now** → execute scrape real; **tanpa** wall-clock timeout / scala yang memutus scrape akun besar (~5000 grup). Hanya idle watchdog (macet tanpa progress) + cancel operator.
      - **Later** → tutup modal → update kolom Session (UI + local + DB) Valid; **tidak** scrape.
   3. Device INVALID → modal **Login** (probe device gagal meski grid masih Valid)
   Bukan: Sync langsung hantar scrape / LOGOUT tanpa Check Session device.

B. SESSION UI = INVALID → Sync:
   → modal **Login** langsung (tanpa Check Session).

C. Login sukses: save session UI+DB saja (tanpa hitung grup) → [Now|Later] atau intent scraper → auto-scrape.
Login FAIL: WA auto-QR; TG error + pesan. Tutup modal = batalkan, session tetap INVALID.
Busy (job queue / Chrome lain): alert busy — **bukan** Valid palsu, **bukan** Scrape Now.

BAGIAN 2: KOLOM LAST UPDATE (real-time)
STANDBY: INVALID → "Use Sync (↻) to log in first"; VALID+MATCH → timestamp saja; VALID+NOT MATCH → timestamp; pending → "—".
RUNNING: bar + X/Y + marquee "Reading groups…".
SELESAI: update group+admin + timestamp; MATCH/NOT MATCH seperti standby.
Tidak ada tombol Run di grid — scrape hanya dari modal Sync.

BAGIAN 3: MODAL LOGIN & QR
Panel lebar (min ~36rem), kotak QR besar (~14rem), skeleton saat generate, overlay expired/gagal + tombol Refresh QR.
WA: auto-regenerate QR. TG: error dulu, refresh manual.

BAGIAN 4: PERFORMA (hingga 5000–6000 grup per akun)
- Sync: Check Session ke device saja (bukan hitung daftar grup).
- Later: session UI+local+DB saja.
- Scrape Now: execute scrape real sampai data akun lengkap; tanpa wall-clock ready timeout; parallel Chrome user max **10**.
- Scrape berhenti sebelum selesai → notif jelas (idle / connect fail / incomplete store / unlink) — bukan diam.
- Incomplete store (kurang dari ~85% count device) → **bukan** sukses; error SCRAPER_INCOMPLETE + coba lagi.
- Idle watchdog + dua fase WA (metadata + invite serial).
- Agregasi master↔daily: accountMasterDailyCompare.ts + RPC rm_commit_account_scrape.
- Issue/kartu: buildTicketSummariesFromEngine.ts; patch grid via patchAccountGridAfterDailyWrite.

BAGIAN 5: CLEAR SESSION (tombol X di kolom Session Valid, hover baris)
Purge session lokal (WA: wa-sessions) + platform_sessions is_active=false + UI Invalid.
Sync berikutnya → open_login (QR bersih). Bukan remove slot. File: clearAccountSession.ts, useAccountSyncFlow.handleClearSession.

BAGIAN 6: METRIK GRID, ISSUE & MODAL GROUP LINK (satu engine)
- Y/X groups & admin: accountMasterDailyCompare.ts — dedupe group_id raw; X = master brand.
- Kartu Issue: buildTicketSummariesFromEngine.ts — angka dari engine (bukan hitung baris DB mentah).
- Breakdown ticket: computeAccountTicketBreakdown (in-memory; sama dengan grid).
- Modal Admin vs master list: fetchAccountGroupLinks — hanya baris master (X).
- Modal Groups on account: fetchAccountDailyGroupLinks — daily akun.
- Grid: kolom On device (groupsCurrent), In brand (joinedInMaster/groupsTotal), Last update (timestamp read-only).
- Export group link: RM-[nama akun]-YYYYMMDD.xlsx.

BAGIAN 7: SESSION PROBE & RESOLVE AKUN (1.0.17)
- Probe device Sync/Scrape: timeout 20s, retry busy — Valid hanya jika device linked; busy → alert (bukan modal Scrape Now / bukan Valid palsu dari disk).
- Device key = messaging_accounts.id baris grid (accountSessionResolve.ts); bukan label global.
- shouldInvalidate DB hanya session mati (UNPAIRED/logout), bukan busy sementara.

BAGIAN 8: DATA FRESH & REALTIME (1.0.17+)
- Scrape: RPC rm_commit_account_scrape atomik (DELETE daily → INSERT → rebuild master).
- Patch grid: patchAccountGridAfterDailyWrite; realtime group_scrape_daily → onAccountDailyChanged (tanpa double-patch master).
- Reload Group matrix + Operations: scheduleMonitoringReload di GroupMonitoringProvider (debounce 500ms) — bukan dispatch ganda dari caller scrape.
- Group matrix (modal header Account): fetch langsung DB + dedupe scraped_at; reload via rm-reporting-reload → BrandMasterGroupsModal.
- Matrix filter kolom Yes/No kosong: header tabel tetap + Back to all groups.
