GM Apps Restructure Plan — Consolidated (agreed with HOD)

Phase 1 — Tab Restructure

  • Remove Reporting as a separate tabMain navigation becomes Account and Operations only
  • Move stock status into the Account brand card
  • Move group matrix access into the Account brand card
  • Confirm Operations opens directly to the Job Queue

Phase 2 — Account & Decision Center Redesign

  • Change top-level card metric from accounts Online to accounts Offline
  • Add top-level card metric for Group/Admin not Aligned
  • Show total group count once per brand card, remove repeated total on each account row
  • Show per-account group count on each account row only
  • Trim brand card status breakdown from Active/Recycle/Ready/Review to to-create count and Review count only
  • Validate against the 3-second detection standard with the R&M team during pilot

Phase 3 — Job Queue Dependency and Account Rules

  • Add brand-photo gate before Create Group execute can run
  • Add Upload Photo requirement inside the Create Group modal when no brand photo exists
  • Auto-queue Set Photo after Create Group completes, when brand photo is available
  • Auto-queue Delete only for groups with confirmed Left status
  • Skip and mark failed for groups where Leave did not succeed, no auto-Delete for those
  • Add failure reason in Remark for Leave and WhatsApp Leave
  • Re-activate Run button for failed tasks so they can be retried from the table
  • Fix Job Queue display so the dialog closes first, then shows the result message, no abrupt reload
  • Lock an account from Create Group selection once it has executed a Create Group task that day
  • Filter Join Missing, Set Admin, and Leave & Delete Chat lists to show only accounts not Aligned

Phase 4 — Telegram Mechanism

Depends on Phase 4 group-type detection being completed before the Upgrade job is used against live data.

  • Add group-type detection field (Supergroup / Basic Group) to Scrape logic
  • Build new Job Queue type: Upgrade to Supergroup
  • Restrict Upgrade to Supergroup execution to accounts holding Creator rights on the target group
  • Test Upgrade to Supergroup on a small sample of groups before wider use
  • Run one-time check per brand: cross-check current Creator/Owner status against GM Apps records
  • Produce output from the check: number of groups no longer usable, number of customers to migrate

Phase 5 — Device-Side Resilience

  • Remove the Telegram scrape quality gate that stops scrapes on many zero member counts
  • Prioritize complete server data for member count and invite links (GetFull-first)
  • Fix Telegram session lock so create/automation jobs do not deadlock
  • Add WhatsApp Leave retries and fallback paths
  • Record WhatsApp Leave failure reason in Remark instead of a bare failed status

Phase 6 — Pilot and Rollout

  • Select a limited set of brands for pilot
  • Apply full restructure (Phases 1-5) to the pilot brands
  • Monitor Create Group account lockout and Leave-to-Delete dependency closely during pilot for unexpected blocking
  • Collect R&M team feedback and metric baselines during pilot period
  • Review pilot results against agreed metrics before extending to full account base
  • Roll out to full account base after successful pilot review
